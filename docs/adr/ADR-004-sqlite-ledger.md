# ADR-004：SQLite 单文件存储 + 账本 append-only + 余额推导

- 状态：已采纳（2026-10-23）
- 出处：技术设计文档 §5、§14

## 背景

原型用 JSON 文件存数据，存在并发写损坏、账本与余额对不上、金额浮点误差等正确性风险。账务正确性是本产品的核心要求。

## 决策

- 存储换 SQLite 单文件（node:sqlite），schema 用编号迁移脚本管理，启动自动迁移。
- 账本表 `ledger_entries` 只追加（append-only）：仓储层不提供更新/删除账本的方法。
- 余额不存可变字段：余额 = Σpurchases − Σledger_entries（按 API 推导）；任务总耗、组排行、项目总账同理由 ledger 聚合。
- 金额一律以最小单位（厘）整数存储与运算，API 出参在边界格式化为元。

## 理由

- 本地单机场景 SQLite 足够且零运维；单文件便于备份与迁移。
- 推导式余额从结构上杜绝「账本与余额对不上」；整数金额杜绝浮点误差。

## 代价

- 聚合查询成本随账本增长上升，现阶段以 tasks 表同事务维护的缓存字段（total_tokens/total_cost_milli）兜列表性能。
