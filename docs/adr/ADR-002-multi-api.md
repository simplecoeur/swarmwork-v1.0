# ADR-002：多 API 并存

- 状态：已采纳（2026-10-23）
- 出处：技术设计文档 §14

## 背景

不同小组的任务对模型能力与价格敏感度不同：文案量大价低、审核要稳、代码要强。只配一条 API 无法兼顾成本与质量。

## 决策

多条 API 并存：每条 API 自带服务商、Base URL、Key、模型、采购单价与余额；按小组分配，小组未指定时走公司默认 API 兜底；至少一条 API 可用（有 Key 且余额 > 0）才能开工，否则任务停工并注明原因。

## 理由

- 成本可按组优化，总经理汇报可按 API 拆账、单独提醒续费。
- 单条线路熔断/欠费不拖垮全公司，其他组可继续工作。

## 代价

- 配置与记账维度增加（账本必须记 apiId，余额按 API 推导），由共享契约与账本模型承接。
